Un “flavor” de LLMs

Una advertencia antes de empezar

Lo que vamos a construir hoy no es un LLM pequeño. Es un modelo estadístico bien conocido —regresión logística multinomial, de la clase 12— aplicado a texto.

Lo que sí es cierto, y es la razón de esta clase: un LLM moderno resuelve, en su capa final, exactamente el mismo problema de clasificación multinomial que ya sabemos resolver. La diferencia es la escala y cómo se construyen los predictores — no la formulación estadística del problema.

El lenguaje como variable categórica

Qué hace, en el fondo, un LLM

Cuando un modelo de lenguaje “escribe”, en cada paso hace exactamente una cosa: dado el texto visto hasta ahora, predice cuál es la siguiente palabra, entre todas las palabras posibles de su vocabulario.

Eso es, formalmente, un problema que ya conocemos:

\mathbb{P}(Y = j \mid X) = \text{softmax}(X\beta)_j, \qquad j = 1, \dots, J

donde Y es la próxima palabra (una categoría entre J posibles) y X es alguna representación de las palabras anteriores. Esta es exactamente la regresión logística multinomial de la clase 12.

Nuestro corpus de juguete

Vamos a trabajar con oraciones de la forma “el SUJETO VERBO los OBJETO”, generadas a partir de un vocabulario pequeño:

set.seed(3070)

sujetos <- c("estudiante", "investigador", "modelo", "algoritmo")
verbos  <- c("analiza", "estima", "predice", "explica")
objetos <- c("datos", "resultados", "modelos", "problemas")
  • Vocabulario total: 4+4+4=12 palabras de contenido (más “el”/“los”).
  • No es un corpus real: lo construimos con una estructura conocida, para poder verificar que el modelo efectivamente la aprende.

Construyendo el corpus

Para que el ejercicio tenga sentido, el sujeto influye en qué verbo es más probable, y el verbo influye en qué objeto es más probable — igual que en el lenguaje real, donde el contexto restringe (sin determinar) la palabra que sigue.

p_verbo_dado_sujeto <- matrix(c(
  .50, .20, .20, .10,   # estudiante
  .20, .50, .10, .20,   # investigador
  .10, .10, .60, .20,   # modelo
  .10, .10, .20, .60    # algoritmo
), nrow = 4, byrow = TRUE, dimnames = list(sujetos, verbos))

p_objeto_dado_verbo <- matrix(c(
  .60, .20, .10, .10,   # analiza
  .20, .20, .50, .10,   # estima
  .10, .60, .10, .20,   # predice
  .10, .10, .20, .60    # explica
), nrow = 4, byrow = TRUE, dimnames = list(verbos, objetos))

Generando 300 oraciones

Predicción binaria

El caso más simple: ¿la próxima palabra es “datos”?

Antes del caso general, empecemos con una pregunta binaria: dado el verbo, ¿el objeto va a ser “datos” o no?

corpus <- corpus %>% mutate(es_datos = as.integer(objeto == "datos"))

m_bin <- glm(es_datos ~ verbo, data = corpus, family = binomial)
summary(m_bin)$coefficients

De binario a multinomial

Reducir “cuál es la próxima palabra” a una sola pregunta binaria descarta información: en un vocabulario de J palabras hay J posibles respuestas, no 2.

La generalización natural —y la que de verdad se usa— es la regresión logística multinomial, que ya vimos en la clase 12:

\mathbb{P}(Y=j \mid X) = \frac{e^{X\beta_j}}{\sum_{k=1}^{J} e^{X\beta_k}}, \qquad j=1,\dots,J.

Esta fórmula —softmax— es, literalmente, la capa final de un LLM: convierte J puntajes reales en una distribución de probabilidad sobre el vocabulario.

Predicción multinomial

El softmax, término a término

Símbolo Significado
J tamaño del vocabulario (número de palabras posibles)
X\beta_j puntaje (logit) de la palabra j, dado el contexto X
e^{X\beta_j} ese puntaje, convertido a un número positivo
\sum_k e^{X\beta_k} normalización: hace que las J probabilidades sumen 1

Con J=2, el softmax se reduce exactamente a la sigmoide de la regresión logística binaria — el mismo resultado que vimos en la clase 12 para el caso multinomial en general.

Ajustemos el modelo multinomial

m_objeto <- multinom(objeto ~ verbo, data = corpus, trace = FALSE)

predict(m_objeto, newdata = tibble(verbo = "predice"), type = "probs")
     datos    modelos  problemas resultados 
    0.139     0.101     0.228     0.532

Dado el verbo “predice”, el modelo asigna la mayor probabilidad a “resultados” — exactamente el patrón que construimos en p_objeto_dado_verbo. El modelo aprendió la estructura del corpus a partir de los datos, sin que se la diéramos explícitamente.

Representación del contexto

¿Qué es “el contexto”, en términos de X?

Para que el softmax funcione necesitamos convertir palabras en números. La forma más simple: variables dummy, una por cada palabra posible del contexto — exactamente como codificamos factor(weathersit) en clases anteriores.

Un LLM real reemplaza estas dummies por embeddings: vectores densos aprendidos que representan cada palabra. La lógica de “convertir una palabra en un vector de números” es la misma; lo que cambia es qué tan compacta y aprendida es esa representación.

Tres formas de representar el contexto

Comparemos tres representaciones, todas prediciendo el objeto:

m0 <- multinom(objeto ~ 1, data = corpus, trace = FALSE)                # sin contexto
m1 <- multinom(objeto ~ verbo, data = corpus, trace = FALSE)            # 1 palabra de contexto
m2 <- multinom(objeto ~ verbo * sujeto, data = corpus, trace = FALSE)   # 2 palabras de contexto

log_loss_multinom <- function(modelo, data, target) {
  probs <- predict(modelo, newdata = data, type = "probs")
  y <- data[[target]]
  idx <- cbind(seq_along(y), match(y, colnames(probs)))
  -mean(log(pmax(probs[idx], 1e-8)))
}

tibble(
  modelo = c("Sin contexto", "1 palabra (verbo)", "2 palabras (verbo + sujeto)"),
  log_loss = c(
    log_loss_multinom(m0, corpus, "objeto"),
    log_loss_multinom(m1, corpus, "objeto"),
    log_loss_multinom(m2, corpus, "objeto")
  ),
  parámetros = c(length(coef(m0)), length(coef(m1)), length(coef(m2)))
)
# A tibble: 3 × 3
  modelo                      log_loss parámetros
  <chr>                          <dbl>      <int>
1 Sin contexto                    1.380          3
2 1 palabra (verbo)               1.120         12
3 2 palabras (verbo + sujeto)     1.060         48

Leer esta tabla

  • El log-loss —la misma métrica de la clase 6 y la clase 18— baja a medida que agregamos contexto: más contexto, mejor predicción.
  • El número de parámetros sube rápido: de 3, a 12, a 48. Con dos palabras de contexto ya necesitamos una interacción completa verbo × sujeto.
  • En un LLM real el contexto son cientos o miles de palabras anteriores. Modelar eso con dummies e interacciones completas —como acabamos de hacer— es completamente inviable: el número de parámetros explota. Los embeddings y la arquitectura Transformer existen, en gran medida, para resolver este mismo problema de forma escalable.

Ajuste e interpretación

Interpretando el modelo elegido

  as_tibble() %>%
  mutate(verbo = verbos, .before = 1)
# A tibble: 4 × 5
  verbo   datos modelos problemas resultados
  <chr>   <dbl>   <dbl>     <dbl>      <dbl>
1 analiza 0.597  0.091    0.078     0.234 
2 estima  0.200  0.543     0.057     0.200 
3 predice 0.139  0.101     0.228      0.532 
4 explica 0.189  0.189     0.568      0.054

Cada fila es una distribución de probabilidad completa sobre el vocabulario de objetos, condicional en el verbo — exactamente lo que un LLM produce en cada paso, solo que aquí el “contexto” es una sola palabra categórica en vez de cientos de tokens representados con embeddings.

Esto ya es “entrenar un modelo de lenguaje”

  • Estimar m1 (vía multinom, que maximiza verosimilitud) es, conceptualmente, lo mismo que “entrenar” una red que predice el siguiente token: ambos minimizan cross-entropy / log-loss (clase 6) sobre ejemplos de contexto → palabra siguiente.
  • La diferencia no es el objetivo de entrenamiento — es la familia de funciones que se usa para pasar del contexto a los puntajes X\beta_j: aquí, una combinación lineal de dummies; en un LLM, muchas capas de una red neuronal (clase 21) operando sobre embeddings.

Generación secuencial

El ciclo de generación

Generar texto, token a token, es un ciclo de cuatro pasos que se repite:

  1. Tomar el contexto actual.
  2. Calcular la distribución de probabilidad sobre la siguiente palabra (softmax).
  3. Muestrear una palabra de esa distribución (no necesariamente la más probable).
  4. Agregar la palabra elegida al contexto, y volver a 1.

Generando oraciones con nuestro modelo

m_verbo <- multinom(verbo ~ sujeto, data = corpus, trace = FALSE)
generar_oracion <- function() {
  sujeto <- sample(sujetos, 1)

  p_verbo <- predict(m_verbo, newdata = tibble(sujeto = sujeto), type = "probs")
  verbo <- sample(names(p_verbo), 1, prob = p_verbo)

  p_objeto <- predict(m1, newdata = tibble(verbo = verbo), type = "probs")
  objeto <- sample(names(p_objeto), 1, prob = p_objeto)

  paste("el", sujeto, verbo, "los", objeto)
}

set.seed(1)
map_chr(1:5, ~ generar_oracion())
[1] "el estudiante analiza los datos"      "el estudiante analiza los modelos"    "el modelo explica los modelos"       
[4] "el investigador estima los modelos"   "el estudiante analiza los resultados"

En cada llamada, el modelo: (1) elige un sujeto, (2) predice un verbo condicional en ese sujeto y muestrea uno, (3) predice un objeto condicional en ese verbo y muestrea uno. Es exactamente el ciclo de la lámina anterior, aplicado dos veces.

Temperatura: controlando qué tan “arriesgada” es la generación

Antes de muestrear, un LLM suele reescalar los puntajes con un parámetro de temperatura T:

\mathbb{P}(Y=j) = \frac{e^{X\beta_j / T}}{\sum_k e^{X\beta_k/T}}.

  • T \to 0: la distribución se concentra en la palabra más probable (generación “conservadora”, casi determinística).
  • T = 1: las probabilidades originales del softmax, sin modificar.
  • T grande: la distribución se aplana — todas las palabras se vuelven casi igual de probables (generación “creativa”, más ruidosa).

Muestrear en vez de tomar siempre el máximo —y ajustar T— es lo que hace que la generación de texto no sea siempre la misma oración, exactamente como en nuestro generador de arriba.

Conexión con los LLM

Tabla comparativa: nuestro modelo vs. un LLM

Elemento Nuestro modelo de juguete Un LLM
Vocabulario 12 palabras decenas de miles de tokens
Representación de entrada variables dummy embeddings (vectores densos aprendidos)
Contexto usado 1–2 palabras anteriores cientos o miles de tokens anteriores
Función de contexto → puntajes combinación lineal (logit multinomial) red profunda tipo Transformer (atención)
Capa de salida softmax sobre objeto softmax sobre todo el vocabulario
Función de pérdida al entrenar log-loss / cross-entropy log-loss / cross-entropy (la misma)
Número de parámetros decenas miles de millones

Qué comparten, y qué no

Comparten: la formulación del problema (predecir el siguiente token es clasificación multinomial), la función de pérdida (cross-entropy), y el ciclo de generación (contexto → probabilidad → muestreo → repetir).

No comparten: la forma de representar el contexto (dummies vs. embeddings aprendidos), la función que va de contexto a puntajes (lineal vs. Transformer con atención), y, sobre todo, la escala.

Por eso la advertencia del comienzo: esto no es un LLM pequeño. Es la misma pregunta estadística, resuelta con las herramientas más simples posibles, para que la pregunta —no la ingeniería— quede clara.

En resumen

  • Predecir la siguiente palabra es un problema de clasificación multinomial — el mismo que vimos en la clase 12.
  • Softmax convierte puntajes en probabilidades sobre un vocabulario; con dos categorías, se reduce a la regresión logística binaria.
  • Más contexto mejora la predicción (menor log-loss) pero aumenta rápidamente el número de parámetros — el problema que los embeddings y los Transformers resuelven a escala.
  • Generar texto es muestrear, repetidamente, de la distribución que el modelo predice — el mismo ciclo, ya sea con un logit multinomial o con un LLM de miles de millones de parámetros.
