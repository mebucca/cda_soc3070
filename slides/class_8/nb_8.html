1. El modelo

Modelamos la probabilidad de que una hora tenga alta demanda (high_demand = 1: bikers por sobre el percentil 75) en función de la temperatura (temp) y la humedad (hum), ambas normalizadas entre 0 y 1:

\[\ln \frac{p_i}{1 - p_i} \;=\; \beta_0 + \beta_1 \,\text{temp}_i + \beta_2 \,\text{hum}_i\]

Code 
modelo <- glm(high_demand ~ temp + hum,
              family = binomial(link = "logit"),
              data = bikedata)

tidy(modelo)
#> # A tibble: 3 × 5
#>   term        estimate std.error statistic   p.value
#>   <chr>          <dbl>     <dbl>     <dbl>     <dbl>
#> 1 (Intercept)    -2.060     0.125     -16.500 7.830e- 61
#> 2 temp            4.630     0.153      30.300 0.000
#> 3 hum            -2.400     0.143     -16.800 4.780e- 63

2. La idea del bootstrap

Queremos la distribución muestral de alguna cantidad estimada. El bootstrap la aproxima sin fórmulas analíticas:

  1. Tomamos una muestra del mismo tamaño que la original, con reemplazo.
  2. Ajustamos el modelo en esa muestra.
  3. Calculamos la cantidad de interés.
  4. Repetimos \(B\) veces y miramos la distribución de los \(B\) resultados.

De esa distribución salen el error estándar (su desviación estándar) y el intervalo de confianza (sus percentiles 2.5 y 97.5).

Code 
set.seed(20260921)
B <- 500   # número de réplicas bootstrap
n <- nrow(bikedata)

En las secciones que siguen repetimos ese mismo ciclo, cambiando solo el paso 3.

3. Bootstrap para un coeficiente: \(\beta_1\)

La cantidad de interés es el coeficiente de temp:

\[\hat{\beta}_1\]

Code 
beta1_bs <- rep(NA, B)   # acá guardamos el resultado de cada réplica

for (i in 1:B) {
  filas   <- sample(1:n, size = n, replace = TRUE)
  muestra <- bikedata[filas, ]
  ajuste  <- glm(high_demand ~ temp + hum, family = binomial(link = "logit"), data = muestra)

  beta1_bs[i] <- coef(ajuste)["temp"]
}

head(beta1_bs)
#> [1] 4.619 4.500 4.470 4.491 4.628 4.521
Code 
beta1_hat <- coef(modelo)["temp"]
ci_beta1  <- quantile(beta1_bs, c(0.025, 0.975))

c(estimacion = beta1_hat, se_bs = sd(beta1_bs), ci_beta1)
#> estimacion.temp           se_bs            2.500%           97.500% 
#>           4.635           0.147           4.349           4.911
Code 
ggplot(tibble(valor = beta1_bs), aes(x = valor)) +
  geom_density(fill = col_dist, colour = col_dist, alpha = 0.25) +
  geom_vline(xintercept = beta1_hat, colour = col_punto, linewidth = 1.1) +
  geom_vline(xintercept = ci_beta1, colour = col_ic, linetype = "dashed") +
  labs(title = expression(paste("Distribución bootstrap de ", hat(beta)[1])),
       subtitle = "Línea sólida: estimación puntual · Líneas punteadas: IC 95%",
       x = expression(hat(beta)[1]), y = "Densidad")

Acá el bootstrap no era necesario: glm() ya entrega el error estándar de \(\hat{\beta}_1\) por máxima verosimilitud. Por eso mismo sirve de control: los dos métodos deberían coincidir.

Code 
se_wald <- tidy(modelo)$std.error[tidy(modelo)$term == "temp"]

tibble(
  metodo = c("Analítico (Wald)", "Bootstrap"),
  se     = c(se_wald, sd(beta1_bs)),
  low    = c(beta1_hat - 1.96 * se_wald, ci_beta1[1]),
  high   = c(beta1_hat + 1.96 * se_wald, ci_beta1[2])
) %>%
  kable(digits = 3)
metodo se low high
Analítico (Wald) 0.153 4.335 4.934
Bootstrap 0.147 4.349 4.911

4. Bootstrap para el odds ratio: \(e^{\beta_1}\)

Ahora la cantidad de interés es una transformación no lineal del coeficiente:

\[e^{\hat{\beta}_1}\]

que se interpreta como el factor por el que se multiplican las odds de alta demanda cuando temp aumenta en una unidad.

Acá ya no hay fórmula directa: el error estándar de \(e^{\hat{\beta}_1}\) no aparece en la tabla de glm(). La ruta analítica exige el método delta, \(\widehat{\text{SE}}(e^{\hat{\beta}_1}) \approx e^{\hat{\beta}_1}\,\widehat{\text{SE}}(\hat{\beta}_1)\), que es una aproximación y además impone simetría. El bootstrap no necesita ninguna de las dos cosas: basta aplicar exp() en el paso 3.

Code 
or_bs <- rep(NA, B)

for (i in 1:B) {
  filas   <- sample(1:n, size = n, replace = TRUE)
  muestra <- bikedata[filas, ]
  ajuste  <- glm(high_demand ~ temp + hum, family = binomial(link = "logit"), data = muestra)

  or_bs[i] <- exp(coef(ajuste)["temp"])
}

or_hat <- exp(beta1_hat)
ci_or  <- quantile(or_bs, c(0.025, 0.975))

c(estimacion = or_hat, se_bs = sd(or_bs), ci_or)
#> estimacion.temp           se_bs            2.500%           97.500% 
#>          102.990           15.690           77.700          140.710
Code 
ggplot(tibble(valor = or_bs), aes(x = valor)) +
  geom_density(fill = col_dist, colour = col_dist, alpha = 0.25) +
  geom_vline(xintercept = or_hat, colour = col_punto, linewidth = 1.1) +
  geom_vline(xintercept = ci_or, colour = col_ic, linetype = "dashed") +
  labs(title = expression(paste("Distribución bootstrap de ", e^{hat(beta)[1]})),
       subtitle = "Línea sólida: estimación puntual · Líneas punteadas: IC 95%",
       x = expression(e^{hat(beta)[1]}), y = "Densidad")

La distribución es asimétrica: la cola derecha es más larga y la estimación puntual no queda al centro del intervalo. El método delta no captura eso.

5. Bootstrap para el efecto marginal promedio de temp

El coeficiente \(\beta_1\) vive en la escala del logit. Para hablar en probabilidades necesitamos el efecto marginal, que en el modelo logístico depende del punto en que se evalúa:

\[\frac{\partial p_i}{\partial \,\text{temp}_i} \;=\; \beta_1 \; p_i \,(1 - p_i)\]

Como ese efecto es distinto para cada observación, lo resumimos promediando sobre la muestra. Es el efecto marginal promedio (AME):

\[\widehat{\text{AME}} \;=\; \frac{1}{n}\sum_{i=1}^{n} \hat{\beta}_1 \; \hat{p}_i \,(1 - \hat{p}_i)\]

Es una función no lineal de los tres coeficientes y de todos los datos. Su error estándar analítico es incómodo de derivar; con bootstrap es una línea más en el paso 3.

Code 
ame_bs <- rep(NA, B)

for (i in 1:B) {
  filas   <- sample(1:n, size = n, replace = TRUE)
  muestra <- bikedata[filas, ]
  ajuste  <- glm(high_demand ~ temp + hum, family = binomial(link = "logit"), data = muestra)

  p <- predict(ajuste, type = "response")
  ame_bs[i] <- mean(coef(ajuste)["temp"] * p * (1 - p))
}

p_hat   <- predict(modelo, type = "response")
ame_hat <- mean(beta1_hat * p_hat * (1 - p_hat))
ci_ame  <- quantile(ame_bs, c(0.025, 0.975))

c(estimacion = ame_hat, se_bs = sd(ame_bs), ci_ame)
#> estimacion      se_bs       2.500%      97.500% 
#>    0.716    0.019    0.676    0.752
Code 
ggplot(tibble(valor = ame_bs), aes(x = valor)) +
  geom_density(fill = col_dist, colour = col_dist, alpha = 0.25) +
  geom_vline(xintercept = ame_hat, colour = col_punto, linewidth = 1.1) +
  geom_vline(xintercept = ci_ame, colour = col_ic, linetype = "dashed") +
  labs(title = "Distribución bootstrap del efecto marginal promedio de temp",
       subtitle = "Línea sólida: estimación puntual · Líneas punteadas: IC 95%",
       x = "AME(temp)", y = "Densidad")

Lectura: la pendiente promedio es 0.716 por unidad de temp, con IC 95% [0.676, 0.752]. Como temp está normalizada entre 0 y 1, una unidad es el rango térmico completo; un aumento de 0.1 en temp corresponde, en promedio, a unos 0.072 en probabilidad.

6. Bootstrap para una curva de predicciones

Hasta acá cada cantidad era un número. También puede ser un vector. Fijamos hum en su media y calculamos la probabilidad predicha a lo largo de una grilla de temperaturas:

\[\hat{p}(\text{temp}) \;=\; \frac{1}{1 + e^{-\left(\hat{\beta}_0 + \hat{\beta}_1 \text{temp} + \hat{\beta}_2 \overline{\text{hum}}\right)}}\]

Cada réplica bootstrap devuelve una curva completa. Guardamos las \(B\) curvas en una matriz: una fila por réplica, una columna por valor de la grilla.

Code 
grilla <- tibble(temp = seq(min(bikedata$temp), max(bikedata$temp), length.out = 40),
                 hum  = mean(bikedata$hum))

curvas_bs <- matrix(NA, nrow = B, ncol = nrow(grilla))

for (i in 1:B) {
  filas   <- sample(1:n, size = n, replace = TRUE)
  muestra <- bikedata[filas, ]
  ajuste  <- glm(high_demand ~ temp + hum, family = binomial(link = "logit"), data = muestra)

  curvas_bs[i, ] <- predict(ajuste, newdata = grilla, type = "response")
}

dim(curvas_bs)
#> [1] 500  40
Code 
# Percentiles columna por columna, es decir, punto a punto sobre la grilla
curva_hat <- grilla %>%
  mutate(p    = predict(modelo, newdata = grilla, type = "response"),
         low  = apply(curvas_bs, 2, quantile, 0.025),
         high = apply(curvas_bs, 2, quantile, 0.975))

ggplot(curva_hat, aes(x = temp, y = p)) +
  geom_ribbon(aes(ymin = low, ymax = high), fill = col_dist, alpha = 0.35) +
  geom_line(colour = col_punto, linewidth = 1.2) +
  labs(title = "Probabilidad predicha de alta demanda según temperatura",
       subtitle = paste0("Curva ajustada y banda bootstrap al 95% (", B,
                         " réplicas); humedad fija en su media"),
       x = "Temperatura normalizada (temp)",
       y = "Probabilidad de alta demanda")

La banda no tiene ancho constante: se abre en los extremos del rango de temp, donde hay menos observaciones.

También podemos mirar algunas curvas bootstrap sin resumirlas. Es la misma información, en crudo:

Code 
# Pasamos 40 filas de la matriz a formato largo para graficarlas
muestra_curvas <- curvas_bs[1:40, ] %>%
  t() %>%
  as_tibble(.name_repair = "unique") %>%
  mutate(temp = grilla$temp) %>%
  pivot_longer(-temp, names_to = "rep", values_to = "p")

ggplot(muestra_curvas, aes(x = temp, y = p)) +
  geom_line(aes(group = rep), colour = col_dist, alpha = 0.3, linewidth = 0.5) +
  geom_line(data = curva_hat, colour = col_punto, linewidth = 1.2) +
  labs(title = "Curvas de predicción bootstrap",
       subtitle = "40 réplicas individuales y, destacada, la del modelo original",
       x = "Temperatura normalizada (temp)",
       y = "Probabilidad de alta demanda")

7. Resumen

Code 
tibble(
  cantidad   = c("beta1", "exp(beta1)", "AME(temp)"),
  estimacion = c(beta1_hat, or_hat, ame_hat),
  se_bs      = c(sd(beta1_bs), sd(or_bs), sd(ame_bs)),
  ci_low     = c(ci_beta1[1], ci_or[1], ci_ame[1]),
  ci_high    = c(ci_beta1[2], ci_or[2], ci_ame[2])
) %>%
  kable(digits = 3)
cantidad estimacion se_bs ci_low ci_high
beta1 4.635 0.147 4.349 4.911
exp(beta1) 102.993 15.687 77.703 140.708
AME(temp) 0.716 0.019 0.676 0.752

Las cuatro secciones corrieron el mismo ciclo. Lo único que cambió fue la línea que calcula la cantidad de interés:

Sección Cantidad Línea del paso 3 ¿Hay fórmula analítica simple?
3 \(\hat{\beta}_1\) coef(ajuste)["temp"] Sí, la da glm()
4 \(e^{\hat{\beta}_1}\) exp(coef(ajuste)["temp"]) No, requiere método delta
5 AME mean(b1 * p * (1 - p)) No, incómoda
6 \(\hat{p}(\text{temp})\) predict(ajuste, newdata = grilla) No, y además es un vector

Pasar de una cantidad simple a una complicada no cambia el procedimiento ni su costo: ese es el atractivo del bootstrap.

Warning

Dos precauciones. La banda de la sección 6 es punto a punto: garantiza 95% de cobertura en cada temp por separado, no para la curva completa a la vez. Y el bootstrap por casos supone observaciones independientes; en bikedata, que son horas consecutivas, hay autocorrelación temporal, así que estos intervalos son algo optimistas.
