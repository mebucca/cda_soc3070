Aprender de los datos existentes y predecir en datos nuevos


Un modelo recibe predictores X y construye una regla:

\widehat{f}:X\longrightarrow \widehat{Y}.


El objetivo predictivo no es reproducir los datos que ya vimos, sino minimizar el error esperado en una nueva observación:

\mathbb{E}\left[L\{Y_{\text{nuevo}},\widehat f(X_{\text{nuevo}})\}\right].


Donde L es una función de pérdida (la función específica depende de la tarea: error cuadrático, error absoluto, log-loss, error de clasificación, etc.)

Nuestro problema de hoy


Usaremos bikers como outcome:

¿Cuántos arriendos habrá en una hora que el modelo no usó para aprender?


Los predictores disponibles describen clima, calendario y hora del día.


No necesitamos comprometernos con una familia de modelos: la lógica de evaluación es la misma para una regresión, un árbol, una red neuronal o cualquier otra regla de predicción.

Overfitting

Buen ajuste no implica buena predicción


Un modelo complejo aprende patrones complejos a partir de los datos. Puede aprender dos cosas:


  • patrones estables que volverán a aparecer (en nuevos datos);
  • ruido idiosincrático de los datos donde ajustamos el model (training set).


La complejidad del modelo ayudar a reducing el error en el training set, pero puede deteriorar la predicción en casos nuevos. Eso es overfitting o sobreajuste.

Tres regímenes de complejidad

  • Subajuste: la regla es demasiado rígida y omite señal.
  • Buen balance: captura patrones reproducibles.
  • Sobreajuste: persigue fluctuaciones que no se repiten.

Más adelante vemos los tres regímenes sobre datos simulados.

Trade-off entre Sesgo y Varianza


En predicción con pérdida cuadrática:

\underbrace{\mathbb{E}\left[(Y-\widehat f(X))^2\right]}_{\text{error esperado}} = \underbrace{\text{Sesgo}^2}_{\text{rigidez}} + \underbrace{\text{Varianza}}_{\text{inestabilidad}} + \underbrace{\sigma^2}_{\text{ruido irreducible}}

sesgo y varianza son dos cantidades distintas que simplemente se sumanl, pero reducir uno suele aumentar el otro: ese es el trade-off sesgo–varianza.


  • El trade-off aparece porque, en la práctica, ambas dependen de la flexibilidad del modelo.

  • Cambio en flexibilidad no cambia sesgo y varianza por separado: cambia la regla de ajuste completa, y eso mueve a ambos a la vez.

Un ejemplo: k vecinos más cercanos

\widehat f(x_0) = \frac{1}{k}\sum_{i \,\in\, N_k(x_0)} y_i \qquad\Longrightarrow\qquad \text{Varianza}(x_0) = \frac{\sigma^2}{k}

k chico (flexible)

  • promedia pocos vecinos, muy cercanos a x_0;
  • sigue de cerca la forma local de f: sesgo bajo;
  • cada vecino pesa 1/k, mucho: varianza alta.

k grande (rígido)

  • promedia casi todos los datos, lejos y cerca;
  • el promedio global ignora la forma local de f: sesgo alto (salvo que f sea constante);
  • cada dato pesa 1/k, poco: varianza baja.

Trade-off entre Sesgo y Varianza


Sesgo alto

El modelo aprende una regla sistemáticamente equivocada.

  • poca flexibilidad;
  • errores parecidos en distintas muestras;
  • riesgo de subajuste.

Varianza alta

Pequeños cambios en la muestra producen reglas muy diferentes.

  • mucha flexibilidad;
  • predicciones inestables;
  • riesgo de sobreajuste.

Sesgo y varianza con datos simulados

Un proceso generador conocido

Para separar sesgo y varianza necesitamos conocer la verdad f. Eso solo es posible simulando:

Y = f(X) + \varepsilon, \qquad f(x) = 2 + 3\sin(2x), \qquad \varepsilon \sim N(0,1) 

f_true <- function(x) 2 + 3 * sin(2 * x)
sigma <- 1
x0 <- 1 # punto donde evaluamos sesgo y varianza más adelante

simulate_training_set <- function(n = 30) {
  x <- runif(n, 0, 3)
  tibble(x = x, y = f_true(x) + rnorm(n, sd = sigma))
}

fit_poly <- function(data, degree) lm(y ~ poly(x, degree, raw = TRUE), data = data)
grid <- tibble(x = seq(0, 3, length.out = 200))

En la práctica nunca observamos f; aquí la conocemos porque la definimos nosotros. fit_poly() es el único ajuste que vamos a reutilizar en todo lo que sigue.

Un primer intento: criterios de información

Penalizar la complejidad dentro de la misma muestra


Criterios de Información:

\text{IC} = \underbrace{-2\log\mathcal{L}_M}_{\text{ajuste}} + \underbrace{k\cdot q}_{\text{parsimonia}}

\text{AIC}=\text{IC}_{q=2},\quad \text{BIC}=\text{IC}_{q=\log n}


  • \mathcal{L}_M: Likelihood maximizada del modelo M; k: número de parámetros.
  • Un valor más bajo indica mejor balance entre ajuste y parsimonia.
  • Como \log(n) > 2 para casi cualquier n en ciencias sociales, BIC castiga la complejidad con más fuerza que AIC.

Dos reglas candidatas


Usaremos estas mismas dos reglas en todo lo que resta de la clase: primero con AIC/BIC, después con validación cruzada.

Limitaciones de los criterios de información


  • Penalizan la complejidad, pero in-sample: nunca miran un caso que el modelo no haya visto al ajustar.
  • Suponen una forma específica de penalización (2k o \log(n)k) que no siempre refleja el costo real de equivocarse.
  • No dicen nada sobre la estabilidad del desempeño entre muestras.

Para saber cómo predice el modelo en casos nuevos, hay que evaluarlo en casos nuevos: ese es el principio

Separar para gobernar

de la validación fuera de muestra.

La regla básica: no usar dos veces los mismos datos


  1. Ajustamos el modelo en el training set.
  2. Congelamos la regla aprendida.
  3. Predecimos el testing set.
  4. Comparamos predicción y resultado con una pérdida.

El “validation set approach” es frágil


Separar una vez en training set y testing set —el validation set approach— evita el doble uso, pero tiene dos problemas:

  1. Alta variabilidad: el error estimado depende de qué casos cayeron en cada lado; repetir el split con otra semilla puede dar un número bastante distinto.
  2. Sesgo por tamaño: el modelo se ajusta con menos datos que los disponibles, y los modelos suelen desempeñarse peor con menos datos. Eso tiende a sobreestimar el error fuera de muestra del modelo final.


Queremos usar todos los datos para entrenar y todos los datos para evaluar, sin usar el mismo caso para ambas cosas a la vez.

Validación cruzada

k-fold cross-validation


Dividimos los datos en k grupos y cada uno actúa una vez como testing set:

\widehat E_{\text{CV}}=\frac{1}{k}\sum_{j=1}^{k}E_j.

El algoritmo es una envoltura genérica

Para j=1,\ldots,k:

  1. reserve el fold j;
  2. ajuste la regla con los otros k-1 folds;
  3. prediga los casos del fold reservado;
  4. calcule la pérdida E_j.

Luego promediamos:

\widehat E_{\text{CV}}=\frac{1}{k}\sum_{j=1}^{k}E_j.

El interior de “ajuste la regla” puede ser cualquier algoritmo predictivo.

El resultado es una distribución, no solo un promedio

Los k errores \{E_1,\ldots,E_k\} permiten estudiar:

  • desempeño promedio;
  • dispersión entre folds;
  • folds especialmente difíciles;
  • sensibilidad de la conclusión a la partición.

Dos modelos con el mismo error promedio pueden diferir mucho en estabilidad.

Sesgo y varianza en la elección de k


k chico (p. ej. 5)

  • entrena con menos datos: algo más de sesgo;
  • los folds comparten pocos casos entre sí;
  • los k errores E_j quedan poco correlacionados \Rightarrow baja varianza al promediar.

k grande, hasta LOOCV

  • entrena con casi todos los datos: sesgo mínimo;
  • los folds casi se superponen entre sí;
  • los errores quedan muy correlacionados \Rightarrow alta varianza al promediar.


Promediar cantidades correlacionadas reduce poco el ruido. Por eso k=5 o k=10 suele predecir el desempeño real mejor que LOOCV, además de costar menos cómputo.
